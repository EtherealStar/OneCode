02 · 项目定位

什么是 OneCode？

OneCode 不是一个 CLI wrapper——
它是围绕 agent 主循环、上下文治理、工具执行、安全边界和能力集成构建的可演化运行时。

01
Harness 工程
大模型作为执行者，工程框架约束它、组织它、承接副作用——让 AI 受控而非失控。
02
薄主循环
主循环只编排"思考—行动—观察"生命周期，不包含任何能力专用分支。
03
文档即接口
架构以文档显式维护，由 AI agent 及开发者按文档执行，遵循文档比遵循 prompt 更重要。
→ 稳定可控的工程框架，不依赖模型"自觉"
→ 所有非核心能力通过生命周期钩子接入
→ 上下文是受管理工作内存，不是无限聊天记录

03 · 系统架构

六层逻辑分层

L1 编排层 AgentLoop 主循环 · ContextEngine · RuntimeState core/loop.py context_engine.py runtime_state.py
L2 上下文与提示 消息链 · transcript · 压缩 · 长期记忆 · 附件投影 · 动态 prompt services/context compaction memory attachments · prompts/
L3 工具与执行 描述符 · 注册表 · schema 投影 · 执行管线 · 结果预算 services/tools/ · tools/*（12+ 内置工具）
L4 安全与扩展 沙箱路径分类 · deny-first 权限 · 生命周期钩子 services/guard permissions hooks
L5 能力集成 子 agent · skill · MCP · 任务系统 · 后台任务 services/subagents skills mcp tasks background_tasks
L6 基础设施与边界 模型协议 · provider 适配 · 配置 · 跨平台路径 · 可观测性 · CLI services/model · infrastructure/* · services/observability · ui/cli
依赖方向约束
core/ 不能 import 具体工具或 provider services/tools/ 不能 import 顶层 tools/ infrastructure/ 不能依赖 core/ guard deny 不能被 hook 覆盖 每一层 只依赖更下层的契约

04 · 核心特性

四大核心机制

01
Agent 主循环
薄而稳定的"思考—行动—观察"循环。确定性状态转换处理错误恢复、预算控制和会话结束。每轮重建上下文，不累积历史。
编排 AgentLoop → ContextEngine → ModelClient → ToolExecutor
02
Hooks 扩展机制
所有非核心能力通过生命周期钩子接入。在主循环关键节点注入工程约束、安全规则和业务逻辑——把仅靠 prompt 无法保证的行为兜底为代码。
新增能力 不需要修改主循环
03
上下文工程
上下文是受管理的工程产物。消息链、transcript、快照每轮动态重建；多级压缩、长期记忆、@mention 附件投影协同工作，确保模型始终看到高信息密度内容。
micro / auto / manual / reactive 四种压缩模式
04
可扩展工具体系
统一工具注册表：描述符定义执行逻辑、权限边界和错误反馈。内置 12+ 工具覆盖文件、命令、检索、子 agent、后台任务等场景。Skill 和 MCP 以同样方式注册。
工具在 受控环境 中执行，异常转化为上下文反馈

05 · 能力集成

模块化能力接入

tools/agent
子 Agent
复杂任务拆解给子 agent（内置 general-purpose / Explore / Plan）。fork child runtime，独立上下文运行。
tools/background_task_stop
后台任务
长耗时 bash、agent 或 dream 任务放入后台。生命周期独立管理，完成时通过通知异步报告。
tools/skill
Skill 技能
领域知识封装为可加载技能。inline（内联指令）或 fork（独立子 agent）两种模式，按需加载。
MCP
MCP 集成
外部工具通过 Model Context Protocol 接入。动态发现、schema 投影、统一执行管线——与内置工具对等。
services/tasks
任务系统
文件持久化的结构化任务管理。依赖图、claim 机制，支持跨会话追踪和多步骤协调。
infrastructure/providers
多 Provider
模型提供方隔离在基础设施层。业务逻辑仅依赖 provider-neutral 协议，在不同厂商间无感切换。

06 · 快速开始

环境准备与启动

1
前置条件
Python 3.11+ · uv 包管理器 · Git Bash（Windows）
2
同步依赖
使用 uv 同步虚拟环境（含开发依赖）
$ uv sync --dev
3
环境变量
复制模板文件，按需配置模型 Provider（也可启动后在终端内用 /connect 命令配置）
$ cp .env.example .env
4
启动 CLI
激活虚拟环境后启动内联终端 REPL（Windows 使用 .\.venv\Scripts\Activate.ps1）
$ uv run python -m ui.cli.app
Batch 模式：当标准输入不是 TTY 时自动进入批处理——
echo "帮我列出当前目录的文件" | uv run python -m ui.cli.app
