OneCode is a **CodeAgent** implemented based on the **Harness** engineering philosophy. It treats the large language model as an executor with tool-calling capabilities, using a stable and controllable engineering framework to constrain, organize, and handle its side effects. This allows the AI to reliably complete long-chain coding tasks in real environments without losing control or crossing boundaries.

## Core Features

### Main Loop
OneCode is built around a thin, stable main loop that drives the agent's "think-act-observe" workflow. The main loop is only responsible for orchestrating the agent's lifecycle: deterministic state transitions handle error recovery, budget control, and session termination, preventing the agent's expanding capabilities from polluting the logic at this layer.

### Extensibility via Hooks
All non-core capabilities are integrated through **Hooks**: developers can inject deterministic engineering constraints, safety rules, and business logic at key nodes of the main loop. This provides a code-level fallback for behaviors that cannot be guaranteed by model prompts alone. Hooks are decoupled from the main loop, meaning new capabilities do not require modifying the main loop itself.

### Context Engineering
OneCode treats the context sent to the model in each turn as an engineering artifact: message chains, transcripts, and snapshots are dynamically rebuilt by the runtime state in each turn. Multi-level compaction, long-term memory, `@mention` attachment projection, and dynamic system prompts work together to ensure the model always sees high-information-density content, rather than an ever-accumulating history of messages.

### Extensible Tool System
All built-in capabilities and external extensions are connected via a unified **Tool Registry**. The registry defines the execution logic, permission boundaries, and error feedback contracts for tools. Tools execute in a controlled environment, and any exceptions are caught and converted into context feedback. Built-in tools cover files, commands, retrieval, attachments, background tasks, sub-agents, etc.; external capabilities are registered in the same way via **Skills** and **MCP**.

### Interruptible and Resumable State
Runtime conversation records and tool invocation histories are independently persisted. After a long task is interrupted, it can resume execution from the breakpoint. All execution records are preserved as replayable trajectories, rather than just kept in memory.

### Observability and Analysis
The system structures and records runtime **traces** and **error logs**: every decision, tool call, and state transition is documented, facilitating subsequent debugging, replay, and evaluation.

### Capability Integration
Complex tasks can be broken down and delegated to **Subagents**, time-consuming operations can be placed in **Background Tasks**, domain knowledge can be encapsulated as loadable **Skills**, and external tools can be connected via **MCP**. All of these are integrated into the main loop as modules, preventing the core layer from bloating due to any single feature.

### Multi-Model Provider Adaptation
Model providers are isolated in the infrastructure layer. The business logic only relies on provider-neutral protocols, allowing easy switching between different model vendors without modifying the agent's runtime logic.

### Tiered Security and Permissions
File path sandboxes, permission decisions, and lifecycle hooks collaborate in tiers. Dangerous operations are intercepted before reaching the execution layer. The system's security boundaries do not rely on the model's "self-awareness."

## Quick Start

OneCode requires **Python 3.11 or higher** and uses [uv](https://docs.astral.sh/uv/) to manage dependencies.

### 1. Prepare Environment

```bash
# Sync virtual environment (including dev dependencies)
uv sync --dev

# Copy environment variable template
cp .env.example .env
```

OneCode's model Provider configuration is read from `.env`. If you prefer not to configure it manually for now, you can directly launch the terminal and use the `/connect` command within the terminal to configure it.

### 2. Launch Terminal

```bash
# On Windows, please activate the virtual environment first
.\.venv\Scripts\Activate.ps1

# Launch the inline terminal REPL
uv run python -m ui.cli.app
```

Batch mode is also supported: it automatically enters batch processing when standard input is not a TTY, for example:

```bash
echo "List the files in the current directory for me" | uv run python -m ui.cli.app
```

## Development Guide

OneCode is a typical harness-style project: the project's target architecture, knowledge map, and working conventions are explicitly maintained as documentation, and then executed by AI agents and developers according to the documentation. In this mode, the documentation itself is the interface, and following the documentation is more important than following the prompt.

- **Understand the Project — Read [`AGENTS.md`](AGENTS.md)**: `AGENTS.md` is the entry file for agents entering this repository. It explains where project knowledge is stored, the recommended reading order, dependency boundary constraints, environment preparation methods, and common commands. When you (or an AI agent) interact with this repository for the first time, you should start with `AGENTS.md`, and then read `architecture.md` and `docs/design-docs/` in the order specified.
- **Read the Design — View [`architecture.md`](architecture.md)**: The root architecture document defines the target runtime structure, logical layering, core abstractions, and dependency direction; for module-level design details, please refer to the corresponding documents under `docs/design-docs/` as needed.
- **Make a Plan — Use [`PLANS.md`](PLANS.md)**: For complex features or major refactoring, an ExecPlan should be written in the format specified in `PLANS.md`, covering everything from design to implementation details. Plans are maintained in `docs/exec-plans/active/`, and archived to `docs/exec-plans/completed/` upon completion.
- **Track Debt — Use [`tech_debt_tracker_guide.md`](tech_debt_tracker_guide.md)**: The project uses a technical debt tracker to record known shortcuts and risks. Please follow this guide when adding or changing debt entries.
- **Run Tests / Boundary Checks**:
  ```bash
  uv run python -m pytest tests -q                    # Full test suite
  uv run python -m pytest tests/test_import_boundaries.py -q   # Dependency boundary check
  uv run python -m compileall core services infrastructure      # Compilation check
  ```
